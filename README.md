# Transaction Ledger API

Backend implementation for the Full Stack Developer Assessment. Built with Node.js, Express, MongoDB and Mongoose.

## Features

- Create accounts with unique generated IDs, system-generated `created_at`, and an initial balance of `0` (client cannot set the balance).
- Credit and debit transactions with amount/type validation.
- Reject debits when funds are insufficient.
- Enforce unique `reference_id` per account and return `409 Conflict` for duplicates.
- Balance endpoint and paginated transaction history with optional `credit`/`debit` filter, newest first.
- Immutable transaction records: there are no update/delete transaction endpoints.
- MongoDB transactions make balance updates and transaction creation atomic.
- Bonus atomic account-to-account transfer with idempotent transfer reference.
- Consistent JSON errors, HTTP status codes, health check, Swagger UI, and automated tests.

## Requirements

- Node.js 18+
- Docker Desktop / Docker Engine (recommended for MongoDB replica set)

MongoDB transactions require a replica set. The supplied Docker Compose configuration runs a single-node replica set for local development.

## Run locally

1. Install dependencies:

   ```bash
   npm install
   ```

2. Start MongoDB replica set:

   ```bash
   docker compose up -d
   ```

   The compose health check initializes replica set `rs0` on first start. Wait until the container is healthy.

3. Create environment file:

   ```bash
   cp .env.example .env
   ```

   On Windows PowerShell, use `Copy-Item .env.example .env`.

4. Start API:

   ```bash
   npm run dev
   ```

   API base URL: `http://localhost:3000/api`
   Swagger docs: `http://localhost:3000/api-docs`
   Health: `http://localhost:3000/health`

## API endpoints

| Method | Endpoint | Purpose |
|---|---|---|
| POST | `/api/accounts` | Create account |
| GET | `/api/accounts/:accountId/balance` | Read balance |
| POST | `/api/accounts/:accountId/transactions` | Add credit/debit |
| GET | `/api/accounts/:accountId/transactions` | Transaction history |
| POST | `/api/transfers` | Atomic transfer (bonus) |

### 1. Create account

`POST /api/accounts`

```json
{ "name": "Atul Deshmukh" }
```

The API always sets `balance` to `0`; a supplied balance is ignored. Returns `201 Created`.

### 2. Credit or debit

`POST /api/accounts/{accountId}/transactions`

```json
{
  "type": "credit",
  "amount": 100.50,
  "description": "Initial deposit",
  "reference_id": "deposit-001"
}
```

Set `type` to `debit` for withdrawals. `amount` must be positive and have no more than two decimal places. `reference_id` must be unique for that account. A repeated reference returns `409`; an insufficient debit returns `422`.

### 3. Balance

`GET /api/accounts/{accountId}/balance`

Example response:

```json
{ "data": { "account_id": "ACCOUNT_ID", "balance": 100.5 } }
```

### 4. Transaction history

`GET /api/accounts/{accountId}/transactions?page=1&limit=10&type=credit`

- `type` is optional; valid values are `credit` and `debit`.
- `page` defaults to `1`; `limit` defaults to `10` and must be `1`–`100`.
- Results are sorted newest first.
- Response contains `current_page`, `page_size`, `total_records`, and `total_pages`.

### 5. Transfer (bonus)

`POST /api/transfers`

```json
{
  "from_account_id": "SOURCE_ACCOUNT_ID",
  "to_account_id": "DESTINATION_ACCOUNT_ID",
  "amount": 30,
  "reference_id": "transfer-001",
  "description": "Rent split"
}
```

Both accounts must exist, they must be different, and the source must have sufficient funds. The debit, credit, ledger entries, and transfer record are committed atomically. The transfer reference must be globally unique.

## Error response format

```json
{ "error": { "code": "INSUFFICIENT_BALANCE", "message": "Insufficient balance" } }
```

Common status codes: `400` invalid input, `404` account not found, `409` duplicate reference, `422` insufficient funds, `500` unexpected server error.

## Tests

```bash
npm test
```

The test suite includes request validation and route behavior using an isolated test app. For full integration testing of database transactions, run MongoDB as configured above.

## Assumptions

1. Account and transaction IDs are MongoDB ObjectIds generated by the server.
2. Amounts are positive numbers with at most two decimal places; account balance starts at zero.
3. `reference_id` is unique within an account for ordinary transactions. For transfers, it is globally unique to prevent duplicate transfers.
4. Transfer ledger entries use `${reference_id}:debit` and `${reference_id}:credit` as account-scoped transaction references.
5. Transaction history only supports reading; no update or delete API is exposed.
6. Pagination `limit` is capped at 100 to avoid unbounded responses.
7. Authentication/authorization was not specified in the assignment and is outside this implementation's scope.
